Architecture Review

NSA Webservice Architecture Friction Points

1. RAG Query-Type Registry Integration

Problem: Five independent query-type vocabularies previously existed with no canonical mapping. ADR-0017 created the registry, but ad-hoc .lower()/ .replace() conversions in consumers still cause boundary failures.

Solution: Enforce registry-resolve-first policy; add compile-time assertions for alias uniqueness.

Benefit: Single source of truth eliminates degraded evaluation entries.

2. Qdrant Filter Seam Consolidation

Problem: Filter construction logic is split between build_filter() (module-level) and QdrantStore._query_filters() (method). Some callers bypass the seam.

Solution: Deprecate _query_filters in favor of build_filter; add a single registration point for payload index fields.

Benefit: One adapter = one seam; fewer bugs from inconsistent filter shapes.

3. Photo Scoring Threshold Optimization

Problem: GATE_THRESHOLD = 0.50 in photo_scoring.py. Measured separation between premises and non-premises images is +0.983.

Solution: Make threshold configurable via PHOTO_SCORING_THRESHOLD with evidence-based default.

Benefit: Better balance between scoring valid premises photos and suppressing non-photo inputs.

4. Inspection Sample Collection Deepening

Problem: Sample collection is a conditional block in the inspection UI with validation spread across sample_utils.py, routes.py, and form handling.

Solution: Extract sample orchestration into a dedicated service layer with a single seam InspectionSampleService.

Benefit: Locality: all sample logic in one place; easier testing; clearer seams for future features.

5. Checklist Polarity Enforcement

Problem: The 12-item checklist has dual polarity: 10 items are violations when stored "no", but artificial_colour and Expired_item are violations when stored "yes". This is the "single most error-prone fact" (CONTEXT.md).

Solution: Add compile-time assertion that all checklist reasoning goes through derive_violations(); add new-module guard for inverted-field awareness.

Benefit: Prevents new code from assuming uniform "no" polarity; makes inversion explicit.

Top Recommendation: Qdrant Filter Seam Consolidation

Why first: This is the foundation that enables cleaner testability and safer Qdrant version upgrades. The seam already exists (build_filter()) but is not fully embraced.

Estimated effort: 2-3 days — consolidate _query_filters calls, add index field registration, update documentation.

Risk: Low — the alternative is maintaining two code paths, which is the current higher-risk state.
