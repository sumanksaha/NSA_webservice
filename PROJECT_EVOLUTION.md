## 6. Architectural Decision Log

1. **Unified `FboIssue` table with `source_type` discriminator**  
   Rather than maintaining separate `InspectionFBO`/`SampleFBO` tables, inspection and sample tracks converge into a single `fbo_issue` table. `source_type` enforces the origin, while a CHECK constraint prevents sample-origin issues from being `dismissed`. This mirrors the real-world convergence point: both tracks ultimately feed the same permission → petition pipeline.

2. **Separate `InspectionPhoto` vs `PhotoEvidence` tables**  
   `InspectionPhoto` is tightly coupled to an `Adjudication` and carries a `file_url` (R2/B2 object key). `PhotoEvidence` is a more general geo-evidence ledger that can attach to either a `CaseFile` or an `Inspection`, and includes IP geolocation, accuracy, and a hash-chained `AuditLog` trail.

3. **Optimistic concurrency via `version_id`**  
   Added `version_id` columns to `Adjudication`, `Bill`, and `CaseFile` (migration `a7776b1a54e3`). SQLAlchemy will raise `StaleDataError` on concurrent edits, which is already handled in `case_file_generator/routes.py`.

4. **Race-safe code generation via `CodeSequence`**  
   A dedicated sequence table with atomic increments (and PostgreSQL advisory locks when available) prevents duplicate `sample_code` / `inspection_code` values across multiple Gunicorn workers.

5. **Date-column normalization from `String(100)` → `DateTime`**  
   Migration `fix_schema_datetime_fk` bulk-upgraded date columns across `sample`, `inspection`, `case_files`, `adjudications`, and `bills`. This replaced fragile string parsing with native datetime filtering.

6. **Google Sheets sync**  
   `app/services/sheets_sync.py` is used from `case_file_generator` to push new case rows. The sheets ID and credentials are configurable via environment variables.

7. **PDF generation via Celery + WeasyPrint**  
   Each `CaseFile` and `Bill` tracks `pdf_task_id` and `pdf_generated_at`. The in-process Celery app (`celery_app.py`) executes `generate_case_file_pdf` and `generate_bill_pdf` tasks. As of the latest code, `.apply()` (synchronous) is used for subprocess compatibility, with a comment to switch to `.delay()` once a persistent worker is deployed.

8. **Security hardening**  
   - `ProxyFix` + Flask-Talisman (CSP, HSTS, secure cookies) enable Render TLS termination without redirect loops.  
   - `flask-wtf` CSRF protection is initialized.  
   - `SECRET_KEY` is mandatory in production; a dev fallback exists with a loud warning.  
   - SESSION cookie flags mirror Talisman for backstop hardening.

9. **FSO data sync at startup**  
   `app/utils/fso_data.py:sync_fso_from_markdown()` runs on every app startup (unless `SKIP_FSO_STARTUP_SYNC` is set), keeping the `fso` table aligned with the markdown source of truth.

# 8. Known Risks / Open Items

- **Auth / RBAC is incomplete** — highest-priority unresolved risk. Anyone with credentials can access every module. There is no role discrimination (FSO vs. admin vs. auditor) and no user self-service or admin UI. `User` model and login are present, but access control stops at `is_authenticated`.
- **Celery worker not guaranteed** — PDF generation currently falls back to synchronous `.apply()`. Without a persistent worker, regeneration is blocking and consumes web-process time. `celery_app.py` references Redis (`redis://localhost:6379/0`), but `redis` is not imported in the code; broker reachability is assumed.
- **Test coverage is module-specific** — `test_fbo_issue.py` is thorough for the state machine, but auth flows, full adjudication end-to-end, and concurrent editing scenarios lack dedicated tests.
- **`InspectionEvent` model unimplemented** — if the inspection workflow requires a chronological event log (status changes, notes, reassignments), this table/blueprint must be designed and added.
- **`Allocation` model unimplemented** — no operator or shift allocation logic exists; if required for workload management, this is a missing piece.
- **String-date parsing in `process_form_data`** — `case_file_generator/routes.py` converts `YYYY-MM-DD` to `DD/MM/YYYY` strings for template rendering, which is brittle if the stored value is already a `datetime` object. The canonical DB storage is now `DateTime`, so template layers should use Jinja filters instead.
- **Unused / loosely coupled dependencies** —
  - `psycopg2-binary` is never explicitly imported in `.py` files (driver loading is implicit via SQLAlchemy).
  - `python-multipart` is listed but never imported; if file uploads are introduced later it may become necessary.
  - `gunicorn` is expected to be absent from imports (WSGI server entry point), but worth confirming it is not required by `render.yaml` or startup scripts.
- **Duplicate/missing index names in migrations** — some migrations create indexes with non-deterministic auto-generated names; SQLite is forgiving but Postgres can raise errors during `flask db upgrade` on a fresh database if head ordering is not strictly linear.
